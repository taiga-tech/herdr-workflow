# テストと受け入れ条件

[文書目次](../README.md) · [更新ルール](../maintenance.md)

> statusは`draft`です。実装済みとして扱う範囲は、コードと試験結果で確認します。

この文書の管理対象：試験ID、入力条件、期待結果、検証状況。

## 試験の状態

T01〜T33は製品の受け入れ条件である。対応する実装と実行結果が記録されるまでは未実装・未実行として扱う。文書の整合検査は、これらの製品試験とは別である。検証結果は実装commit、Herdr版、OS、日付とともに記録する。

## テストと受け入れ条件

| ID                  | 試験内容                                                    | 期待結果                                          |
| ------------------- | ----------------------------------------------------------- | ------------------------------------------------- |
| <a id="t01"></a>T01 | 未知キー、重複キー、未定義変数                              | 外部操作前に位置付きエラー                        |
| <a id="t02"></a>T02 | 循環依存                                                    | 循環するTask IDの経路を表示                       |
| <a id="t03"></a>T03 | serviceへの`succeeded`依存                                  | 設定検証で拒否                                    |
| <a id="t04"></a>T04 | `mise install`失敗                                          | pnpm、配置、Agentを開始しない                     |
| <a id="t05"></a>T05 | サーバーreadinessが遅れる                                   | E2Eを準備完了まで開始しない                       |
| <a id="t06"></a>T06 | readiness前にプロセス終了                                   | 待機を終了して失敗を記録                          |
| <a id="t07"></a>T07 | 別プロセスがポート使用中                                    | 誤ってreadyにせず、起動を保留・失敗にする         |
| <a id="t08"></a>T08 | serviceがready後に終了                                      | 依存側に設定した停止規則を適用                    |
| <a id="t09"></a>T09 | 複数serviceと後続job                                        | service数がjob用実行枠を塞がない                  |
| <a id="t10"></a>T10 | Agentがidleになる                                           | job成功へ自動変換しない                           |
| <a id="t11"></a>T11 | 同じ作成イベントが重複                                      | 同じ初期化を並行して開始しない                    |
| <a id="t12"></a>T12 | 自分のupから作成イベント受信                                | 別Runを増やさない                                 |
| <a id="t13"></a>T13 | Git作成成功・応答保存前の停止                               | 実状態を照合し、worktreeを増殖させない            |
| <a id="t14"></a>T14 | 子プロセス起動直後の停止                                    | 状態不明を保持し、無断再実行しない                |
| <a id="t15"></a>T15 | Coordinatorの再起動                                         | 既存Runnerと結果を照合し、稼働jobを重複起動しない |
| <a id="t16"></a>T16 | 古いAttemptの遅延通知                                       | 新しいAttemptの状態を上書きしない                 |
| <a id="t17"></a>T17 | Herdr接続切断・再接続                                       | 古いpane IDを照合せず操作しない                   |
| <a id="t18"></a>T18 | CLI作成とTUI作成                                            | 各対象Herdr版で同じ適用方針になる                 |
| <a id="t19"></a>T19 | grid重複、範囲外、分割不能                                  | 配置開始前に拒否                                  |
| <a id="t20"></a>T20 | 利用者が既存ペインを変更                                    | resumeでそのペインを置換しない                    |
| <a id="t21"></a>T21 | ログペインを閉じて再表示                                    | 実行中serviceを再起動しない                       |
| <a id="t22"></a>T22 | コピー先が追跡済み、パス脱出、symlink                       | ファイルを変更せず拒否                            |
| <a id="t23"></a>T23 | コピー途中の失敗                                            | 記録された変更だけを復旧し、復旧不能分を示す      |
| <a id="t24"></a>T24 | 未承認リポジトリの作成イベント                              | 自動コマンドを実行しない                          |
| <a id="t25"></a>T25 | 設定変更後の自動実行                                        | 古い承認で実行しない                              |
| <a id="t26"></a>T26 | stop時に子孫プロセスが残る                                  | 対象を照合して停止し、残存分を報告                |
| <a id="t27"></a>T27 | dirty / untracked / ignoredなファイルがある削除             | 内容を確認せず削除しない                          |
| <a id="t28"></a>T28 | 外部からworktreeが消える                                    | 削除済みパスを作り直さず、状態を更新              |
| <a id="t29"></a>T29 | ログディスク満杯、DB書き込み失敗                            | 劣化を通知し、新規起動を安全側に止める            |
| <a id="t30"></a>T30 | Agent用プロンプトの送信応答を失う                           | 同じプロンプトを無断再送しない                    |
| <a id="t31"></a>T31 | 同一checkoutを別Herdrセッションから操作                     | checkoutロックで初期化を直列化                    |
| <a id="t32"></a>T32 | Linux、macOS、WSL                                           | パス、信号、ログ、通信の契約試験を通過            |
| <a id="t33"></a>T33 | プラグイン全体設定の誤記、範囲外、grid寸法・tab内pane数超過 | 外部操作前に設定エラーとして拒否                  |

設定例は意味検証の固定テストにする。プロセス試験には制御可能な小さなHTTPサーバー、遅延終了、大量ログ、子孫プロセスを作るfixtureを使用する。実エージェントを起動する試験は明示的な有効化制とし、通常のCIで利用者の認証や課金を使わない。

## 実装時の試験層

| 層           | 対象                                         | 外部依存                         |
| ------------ | -------------------------------------------- | -------------------------------- |
| 単体         | 設定の意味検証、DAG、grid、状態遷移          | Herdrや実Agentを使わない         |
| プロセス契約 | timeout、readiness、出力、子孫停止、異常終了 | 制御用fixtureを使う              |
| Herdr契約    | APIの形、event、workspace、tab、pane、再接続 | 対応表に記載するHerdr版          |
| 受け入れ     | T01〜T33を含む一連の運用                     | 対象OSと明示的に承認した認証情報 |
| 障害注入     | 応答消失、書き込み失敗、再起動、重複通知     | 外部副作用を制御できる試験環境   |

機能追加時は既存IDを振り直さず、新しいT番号を追加する。T33以降は文書移行後に追加した試験であり、T01〜T32の保存済み移行基準とは分けて管理する。Windowsネイティブや対話Runnerの試験は、Linux/WSL試験の成功を根拠に省略しない。
