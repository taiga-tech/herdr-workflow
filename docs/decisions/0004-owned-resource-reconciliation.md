# ADR-0004：所有権と照合による復旧

[文書目次](../README.md) · [更新ルール](../maintenance.md)

この文書の管理対象：一つの判断の背景、選択と結果。現在の動作規則は関連仕様を参照する。

## 背景

同じイベントの重複や応答消失が発生すると、操作を再実行してよいか判別できない場合がある。利用者のペイン、checkout、ファイルを本プラグインの所有物と誤認すると、復旧操作自体が変更の消失につながる。

## 提案する決定

Run開始時の計画を固定し、操作と所有権、Attempt、checkout世代を記録する。応答を失った変更要求は実状態と照合し、不明な状態を`unknown`として保持する。`resume`では既存タブを置換しない。

## 比較した案

同じパスやPIDを同じ対象と見なす案、変更要求を即座に再送する案、レイアウトを再作成して復旧する案は初期案から除外する。

## 結果と制約

記録と外部操作が不可分になるわけではない。処理済みか不明な外部副作用を一度だけにする保証は行わない。借用リソースの削除を避け、必要な場合は利用者の確認を求める。

## 採用条件

T11〜T17、T20、T22〜T28、T31を検証する。状態の保存先や証跡の形式はQ12、差分確認はQ15で詰める。
