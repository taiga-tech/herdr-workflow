# ADR-0006：利用者固有のプラグイン全体設定

[文書目次](../README.md) · [更新ルール](../maintenance.md)

この文書の管理対象：一つの判断の背景、選択と結果。現在の動作規則とキーは[設定リファレンス](../reference/configuration.md)を参照する。

## 背景

workflow設定はリポジトリが所有し、Taskやレイアウトを共有する。一方、資源消費の上限、承認、表示等の利用者固有設定は複数のworkflowへ共通に適用する必要があり、リポジトリから安全上限や利用者の判断を変更できてはならない。

## 決定

利用者固有のプラグイン全体設定を`$HERDR_PLUGIN_CONFIG_DIR/config.yaml`に置く。workflow設定とは独立したスキーマ版を持ち、未知キー、重複キー、未対応版、範囲外の値を拒否する。

ファイルまたは環境変数がない場合は組み込み既定値を使う。ファイルが存在する場合の読み取り・構文・値エラーは既定値へフォールバックせず、外部操作前に報告する。

プラグイン全体設定はworkflow設定より強い利用者側の制約として適用し、workflow設定から上書きする構文は設けない。計算量を制限する値には、設定で解除できない安全上限も実装に保持する。初期版ではgrid各軸の安全上限を64、一つのtabのpane数上限を32とし、設定では引き下げることだけを許可する。測定なしにこれらを引き上げない。

## 比較した案

`.herdr/workflow.yaml`へ利用者設定を追加する案は、リポジトリごとに重複し、リポジトリ側が利用者の上限を変更できるため採らない。`herdr-plugin.toml`へ追加する案は、プラグインのaction宣言と利用者の実行時設定を混在させるため採らない。環境変数ごとに値を追加する案は、設定項目が増えたときの発見性と構造化検証に劣るため採らない。

## 結果と制約

設定追加時は[設定リファレンス](../reference/configuration.md)を主文書として、既定値、許容範囲、欠落・不正時の挙動を定義する。秘密値そのものはこのファイルへ保存せず、必要になった時点で秘密値参照の契約を別途定める。

初期設定はgrid各軸とtabごとのpane数の運用上限を持つ。絶対上限の引き上げはgrid面積、pane数、重複検査と境界探索の時間、および対象Herdr版での実動作を測定した後に判断する。workspace全体のpane数等、必要な追加上限は運用実績に基づいて定める。今後の設定は責務別のトップレベル領域へ追加し、スキーマ版の互換性を確認する。
