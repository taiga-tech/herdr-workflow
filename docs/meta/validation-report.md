## 本文の移管確認

元文書の通常段落157件について、移管後の本文に存在することを照合した。表とコードブロックはこの段落照合から除外し、資料への参照表記と、分割によって変更した「以下」「前節」の指示先を正規化して比較した。

設定の全文例はYAMLへ分離した。旧ディレクトリ図は現在の文書構成と実装予定を区別する図に更新した。その他の表や図を含め、元の全文は変更せずarchiveに保存している。機械的な照合だけで全記述の意味が等しいことを証明したとは扱わない。

## 設定例の補助検査

YAML構文の読み込み、Task IDと依存先の参照、依存条件、循環依存の不在を確認した。6タスクのうちbootstrap対象は3つのjobであり、serviceとAgentを含まない。

配置は6列×2行の12セルに5ペインを置く構成。範囲外、重複、未配置セルがなく、矩形を横切らない二分割木へ変換できることを確認した。AgentタスクとAgent用ペインの対応も確認した。現行のYAMLは元の設定例とバイト単位で一致する。

この補助検査は設定例を対象にしたもので、未実装のRustパーサーや完全なJSON Schemaへの適合を検証したものではない。

## 次回更新時

通常の更新では`python3 scripts/check_docs.py`を実行する。`--check-migration`は元の受け入れ条件との完全一致を確認する移管用オプションである。正式に仕様を改定した後は、過去の文言との一致を恒常的な制約にせず、変更履歴とADRを残して現行仕様を検証する。

この記録は文書版0.2の検査時点を表す。後日ファイルを編集した場合は、新しい検査日と結果を記録する。
