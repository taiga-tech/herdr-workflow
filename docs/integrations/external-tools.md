# 既存プラグインと外部ツール

[文書目次](../README.md) · [更新ルール](../maintenance.md)

> statusは`draft`です。実装済みとして扱う範囲は、コードと試験結果で確認します。

この文書の管理対象：外部処理をTaskとして扱う契約、再利用と競合の扱い。

<a id="source-21"></a>

## 既存プラグインと外部ツール

既存プラグインの再利用は許容する。ただしDAG、状態管理、実行順の制御を外部へ分散させない。

外部処理を一つのTaskとして扱う場合は、起動受付、処理完了、成功条件、キャンセル方法、ログの取得方法をアダプターで定義する。Herdrのaction呼び出しが返っただけでは、実際のセットアップ完了と判定しない。

| 対象機能                         | 本設計での扱い                                                  |
| -------------------------------- | --------------------------------------------------------------- |
| ファイルコピー                   | 原則として内部実装。コピー条件と復旧方法を同じ計画で扱う        |
| 初期化コマンド                   | 外部CLIをTaskRunnerから実行する                                 |
| 既存レイアウトプラグイン         | 手動呼び出しと完了確認が可能な場合に限定して接続                |
| 外部worktree管理ツール           | 作成結果のcheckoutとHerdr workspaceを照合するアダプターを設ける |
| fetch、upstream設定、pull/rebase | 明示設定した追加処理として扱う。既定では実行しない              |
| ブランチ名による構成選択         | 後続のprofile機能で、最初に一致したルールと選択結果をplanに表示 |
| 削除候補の検出                   | review用一覧を作る。リモート参照消失だけで自動削除しない        |

同じworktree作成イベントに反応する他プラグインが有効な場合は警告する。`doctor`はHerdrの`plugin.list`で、有効で`worktree.created`・`worktree.opened`のイベントを登録した他のプラグインを示す。競合する初期化を止めるために、利用者のプラグインを自動無効化しない。

<a id="profiles"></a>

### ブランチ名による構成選択

workflow設定の`profiles`をブランチ名で上から照合し、最初に一致した一つを適用する([設定](../reference/configuration.md))。ブランチ名は`worktree.branch`の値置換の結果とし、`attach`で`branch`を省略した場合は対象checkoutの現在のブランチとする。適用できるのは入力の既定値と`bootstrap.targets`の置き換えに限る。CLIで明示した入力はprofileより優先する。

選んだprofileは`plan`の出力(`profile`)とRunのイベント(`profile: <id>`)に表示する。適用後の構成から実行計画を作るため、実行計画ハッシュも変わる。ブランチ名で選んだ結果がブランチ名を変えると循環するため、`worktree.branch`で参照する入力はprofileで変えられない。profileは設定本文に含まれるため、承認の設定ハッシュの対象になり、`trust`の表示にも含める。

<a id="herdr-action"></a>

### Herdrプラグインのaction

commandタスクの`herdrAction`は、他のHerdrプラグインのactionを一つのjobとして実行する。Herdr v0.9.5の公開APIで次のとおり扱う。[S1](../reference/sources.md#s1)

| 項目       | 扱い                                                                                                                                   |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 起動受付   | `plugin.action.invoke`。文脈には`workspace_cwd`(タスクの作業ディレクトリ)と、取得できれば`workspace_id`を渡す                          |
| 処理完了   | 応答に含まれる実行記録のIDを`plugin.log.list`で照会し、`status`が`succeeded`・`failed`になるまで待つ。呼び出しの応答だけで完了としない |
| 成功条件   | `succeeded`を成功、`failed`を記録の終了コード(なければ1)の失敗とする。記録が見つからなくなったら失敗にする                             |
| キャンセル | 公開APIにactionのコマンドを止める手段がないため、停止要求では照会をやめて終了し、action側が動き続けうることをログに残す                |
| ログ       | 完了時に記録の標準出力・標準エラーをこのjobのログへ写す                                                                                |

このjobは本プラグインの実行ファイルを`herdr-action`として起動するため、実行期限、再試行、ロック、依存関係は通常のjobと同じ扱いになる。Herdrの接続先(`HERDR_SOCKET_PATH`)がない場合は、外部操作の前にRunを拒否する。他のプラグインのコマンドを実行するため、`trust`の表示にaction IDを含める。

コードを取り込む場合はlicenseと著作権表示を調査する。公開APIだけで連携する方式と、コードを再利用する方式を分けて判断する。
